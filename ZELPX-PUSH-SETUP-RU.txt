ZELPX — ИСПРАВЛЕННЫЙ ПАКЕТ PUSH-УВЕДОМЛЕНИЙ
================================================

СТАТУС
Это рабочая копия для проверки. Она НЕ загружена в GitHub, НЕ опубликована в Vercel,
а SQL и Edge Function НЕ применены к рабочему Supabase.

ЧТО ИСПРАВЛЕНО
1. Кнопка уведомлений теперь появляется не только при загрузке страницы с уже активной
   сессией, но и после входа пользователя. Раньше скрипт проверял сессию один раз при
   открытии страницы и мог вообще не показать кнопку после обычного входа.
2. Подписка повторно использует существующую push-подписку устройства.
3. Уведомление на заблокированном экране содержит нейтральный текст, а не содержание
   личного сообщения.
4. Серверная функция адресует уведомление второму участнику переписки и удаляет
   недействительные подписки (HTTP 404/410).

ФАЙЛЫ
- zelpx-push.js — кнопка и регистрация подписки.
- zelpx-sw.js — показ push и переход по нажатию.
- supabase-chat-push.sql — таблица подписок и RLS.
- supabase/functions/send-chat-push/index.ts — серверная отправка.
- index.html и customer.html — подключение скрипта.
- остальные файлы — сопутствующая рабочая копия портала; не нужно загружать их в Supabase.

ВАЖНО: ДЛЯ РАБОТЫ НУЖНЫ VAPID-КЛЮЧИ
Public Key вставляется в zelpx-push.js вместо ADD_VAPID_PUBLIC_KEY_HERE.
Private Key хранится ТОЛЬКО в Supabase Secrets и никогда не помещается в HTML,
JavaScript, GitHub или ZIP.

ГЕНЕРАЦИЯ КЛЮЧЕЙ
На компьютере с Node.js выполнить:
  npx web-push generate-vapid-keys

Сохранить оба значения в надёжном месте. Public Key использовать в zelpx-push.js.
Private Key никому не отправлять в чат и не публиковать.

НАСТРОЙКА SUPABASE (только после резервной копии и отдельного разрешения)
1. Открыть проект zelpx-database → SQL Editor.
2. Выполнить только файл supabase-chat-push.sql.
3. В Edge Functions → Secrets добавить:
   VAPID_PUBLIC_KEY = публичный ключ
   VAPID_PRIVATE_KEY = приватный ключ
   VAPID_SUBJECT = mailto:ваш-адрес-поддержки
   CHAT_PUSH_WEBHOOK_SECRET = длинная случайная строка
   SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY — системные секреты проекта.
4. Развернуть функцию send-chat-push из папки supabase/functions/send-chat-push.
   Требуется включённая проверка webhook-секрета; verify_jwt выключается только для
   Database Webhook, потому что запрос проверяется заголовком x-webhook-secret.
5. В Database → Webhooks создать webhook:
   table public.lead_messages, event INSERT,
   URL https://zsrnjkndgbchfxibxiyd.supabase.co/functions/v1/send-chat-push
   header x-webhook-secret = тот же CHAT_PUSH_WEBHOOK_SECRET.
6. Перед публикацией заменить placeholder на VAPID PUBLIC KEY в zelpx-push.js.
7. Сначала опубликовать в Preview, проверить двумя тестовыми аккаунтами и двумя устройствами.
   Только после успешного теста решать отдельно, публиковать ли Production.

НЕ ВЫПОЛНЯТЬ
- Не вставлять VAPID Private Key в исходники.
- Не открывать SELECT для всех на chat_push_subscriptions.
- Не удалять старые сообщения, аккаунты, чаты или RLS-политики.
- Не заменять Production без отдельного подтверждения.

ПРОВЕРКА
1. Войти в ZELPX как заказчик. Кнопка должна появиться после входа без перезагрузки.
2. Разрешить уведомления и отправить сообщение тестовому подрядчику.
3. Войти на втором устройстве как подрядчик, разрешить уведомления и ответить.
4. Проверить уведомления при закрытой вкладке и нейтральный текст на экране блокировки.
5. Повторить тест после выхода и повторного входа.
