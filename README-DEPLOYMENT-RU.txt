# ZELPX — комплект для предварительной проверки (НЕ опубликован)

Это локальная подготовительная копия. Изменений в GitHub, Vercel, Supabase, Stripe или на Production не выполнялось.

## Состав
- `index.html` — кабинет подрядчика; пользователь с ролью Admin перенаправляется на `/admin.html`.
- `admin.html` — отдельная страница администратора.
- `customer.html` — кабинет клиента с чатом для заявки, у которой уже есть `lead_id` и запись в `lead_conversations`.
- `customer-chat.html` — прежний чат по приватной ссылке; скопирован без изменений.
- `chat-access-policies.sql` — предлагаемые дополнительные политики; файл скопирован без изменений и НЕ разрешён к запуску.
- `vercel.json` — прежние маршруты; скопированы без изменений.

## Важное ограничение чата
Кабинет клиента не создаёт новую переписку. Он читает и отправляет сообщения только если для заявки уже существует запись `lead_conversations`. Это сделано намеренно: без схемы БД нельзя безопасно предполагать обязательный `contractor_id` и способ создания переписки. Если переписка ещё не создана, клиент увидит пояснение.

## Обязательные проверки до публикации
1. Сверить SQL с действующей схемой Supabase: RLS, все существующие политики, ограничения и внешние ключи, значения `profiles.role`.
2. Подтвердить, что RPC `get_or_create_lead_conversation` и Edge Function `create-customer-chat` создают ожидаемую запись `lead_conversations`.
3. Проверить в отдельной тестовой среде аккаунты клиента, подрядчика и администратора. Убедиться, что клиент не читает чужие переписки, администратор не может отправлять сообщения, а подрядчик видит только купленные заявки.
4. Повторно протестировать регистрацию и подтверждение email, Stripe Checkout и webhook, начисление кредитов, `buy_lead`, доступ к контактам и приватный чат по токену.
5. После успешной проверки сначала опубликовать Preview, а не Production.

## Сохранение существующих функций
Код оплаты и покупки в кабинетах подрядчика/администратора намеренно не менялся. Приватный чат по токену и маршруты Vercel скопированы без изменений. Этот архив — подготовленная версия исходников, а не подтверждение работы реальных интеграций.
